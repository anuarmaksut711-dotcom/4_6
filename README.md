# PIXEL — 4_6

Сайт компьютерного клуба PIXEL: каталог игр, выбор зала, расчёт визита и заявки администратору в Telegram.

## Основа и HTML/CSS freeze

Сохранены оригинальные страницы, CSS, 3D-портал, фотографии, обложки игр, форма и калькулятор. Контрольные суммы HTML/CSS зафиксированы в tests/site_baseline.json.

## JavaScript и данные

- js/main.js: общие DOM-функции, classList-состояния, форматирование цены, генерация демонстрационного номера и интеграция существующей навигации с общей корзиной.
- js/games.js: массив 20 объектов с ID, названием, жанром, поисковыми названиями и шаблоном исходной карточки. renderCard используется для всех карточек; сохранены изображения, текст, классы и действия. Связанные поиск и жанр используют filter, every, map и нормализацию.
- assets/club-pricing.json: 14 реальных позиций с ID, залом, названием, ценой, типом и условиями. packages.js проверяет данные и обслуживает корзину. booking.js создаёт повторяющиеся строки пакетов из этого массива.
- package-pricing.js: единая прежняя модель расчёта пакетов; цена пакетов на каждого игрока плюс почасовая доплата за время вне покрытия. Это предварительная модель сайта, условия подтверждает клуб. Сохранены существующие правила, не вводится новая схема расчёта.
- booking.js: валидация имени после trim, телефона, целых чисел, дат/времени, вместимости, зала/ПК и связанных тарифных условий; есть пустые и неверные состояния. Сводка обновляется при изменениях. booking-delivery.js обращается только к API того же сайта; повтор неизменённой заявки использует тот же криптографический идентификатор. Math.random применяется только к демонстрационному номеру корзины.
- Используются const/let, строгие сравнения, арифметика, && и ||, циклы, filter/find/map/reduce и функции с параметрами/возвращаемыми значениями. integer, validDate, validTime, isPast, hourlyEstimate и calculate обслуживают логику; функции вызывают друг друга.
- Новые события: click, input, change, submit и storage. Пользовательский текст выводится через textContent. Состояния используют существующие d-none, active, is-invalid и success-message.

## Запуск

```powershell
python booking_server.py --port 8898
```

Открыть http://127.0.0.1:8898/index.html. Нужен Python 3.10+ без сторонних зависимостей и приватный env/.env с настройками Telegram; PUBLIC_ORIGIN=http://127.0.0.1:8898. Применяются отдельные ключи pixel-assignment-*, сохраняющие данные этой копии отдельно от действующей версии. Имя и телефон передаются администратору, но не записываются в браузер или базу сервера. Недоступность localStorage не отменяет успешную доставку.

## Проверка

```powershell
node --test tests/test_packages.cjs
python tests/check_coursework.py
python -m unittest discover -s tests -p test_booking_server.py -v
python booking_server.py --dry-run --port 8899
# В другом терминале:
node tests/coursework-browser.cjs
node tests/booking-delivery-browser.cjs
```

Браузерный тест использует уже установленный Playwright/Chromium, без установки зависимостей проекта. Проверяются оформление пяти страниц, каталог, форма, корзина, мобильная сводка, успех/ошибки отправки и отсутствие консольных ошибок. Отправка проверяется только на --dry-run сервере или с подменой ответа API; сообщения администратору не отправляются. Подробности — demofinal/QA.md.

## Замена графической зависимости

Для сохранения прежнего оформления портал переведён с Three.js на нативный WebGL. Геометрия сцены и запечённые материалы остаются статическими ресурсами проекта, движение и отрисовка выполняются браузерным API без стороннего JavaScript. Необходимое исправление подключения: удалены неиспользуемый importmap для Three.js и её файлы из публичной папки. Это служебная настройка скрипта, не изменение интерфейса; HTML-элементы страницы и CSS сохраняются.

## Локальная настройка Telegram

Настоящие токен бота и ID получателя хранятся в приватном env/.env за пределами demofinal/. Этот файл исключён из Git и архива публичного сайта. .env.example остаётся пустым шаблоном. При запуске booking_server.py кнопка «Забронировать» передаёт данные администратору в Telegram. Места подтверждает администратор. Тестовый режим --dry-run не обращается к Telegram. Подробности — TELEGRAM_SETUP.md. Статический сервер не выполняет отправку: при недоступном API форма не показывает ложное подтверждение. На телефоне перед ней сохраняется отдельный шаг «Проверить план».
