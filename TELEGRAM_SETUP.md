# Заявки PIXEL в Telegram

Сервер принимает имя, телефон и план визита, проверяет данные и отправляет сообщение одному получателю: администратору или в группу. Места автоматически не резервируются — администратор подтверждает их гостю.

## Подключение бота

1. Создайте бота через [BotFather](https://t.me/BotFather).
2. Вставьте токен в `env/.env` после `TELEGRAM_BOT_TOKEN=`. Для новой копии создайте этот файл по .env.example. Не перезаписывайте заполненные настройки.
3. Для личных уведомлений администратор должен открыть бота и нажать «Старт». Для группы — добавьте бота и отправьте в группе `/start@имя_бота`.
4. Выполните из корня рабочей копии `python list_telegram_chats.py`. Команда только читает список доступных чатов, не отправляет сообщения и не печатает токен.
5. Впишите ID нужного получателя в `TELEGRAM_CHAT_ID=`. Для группы ID обычно отрицательный. Если используется конкретная тема группы, заполните также `TELEGRAM_MESSAGE_THREAD_ID`.

При пустом списке сначала напишите боту и повторите команду. Для существующего бота с webhook используйте уже известный ID чата; вспомогательная команда webhook не удаляет.

## Запуск

Python 3.10 или новее, сторонние зависимости не нужны:

```powershell
python booking_server.py --port 8898
```

Откройте `http://127.0.0.1:8898/booking.html`. Изменения токена и ID чата подхватываются при перезагрузке страницы; перезапуск для них не нужен. Пока настройки не заполнены, форма сообщает, что отправка недоступна, и не показывает ложное подтверждение.

Для новой копии проекта создайте `env/.env` по `.env.example`. Настоящий файл настроек, папка `env/` и база `var/` исключены из Git. HTTP-сервер раздаёт только `demofinal/`, запрещает скрытые файлы, выход за корень и просмотр каталогов. Токен не попадает в HTML/JavaScript и ответы API.

Для размещения нужен сервер Python и HTTPS на публичном адресе, например через обратный прокси. Укажите точный адрес сайта без завершающего `/` в `PUBLIC_ORIGIN` и перезапустите сервер. Обычный статический хостинг или `python -m http.server` не выполняют отправку заявок. На публичном прокси настройте ограничения частоты запросов; встроенное ограничение использует адрес прямого подключения.

## Проверка без сообщений

```powershell
python booking_server.py --dry-run --port 8899
```

Откройте `http://127.0.0.1:8899/booking.html`. Тестовый сервер не обращается к Telegram даже при заполненном токене; результат явно назван тестовым. Этот режим разрешён только на локальном адресе. Браузерные тесты используют этот адрес по умолчанию и отказываются выполнять отправку на живом сервере.

Автоматические проверки:

```powershell
python -m unittest discover -s tests -v
node --check demofinal/js/booking.js
node --check demofinal/js/booking-delivery.js
```

Все серверные тесты используют подмену отправителя и не отправляют внешние сообщения. Проверяются контакты, вместимость, дата/время, пакеты, серверный пересчёт, повторные/одновременные запросы, ошибки доставки, недоступные настройки, ограничение частоты, Origin, JSON и недоступность секретных файлов.

## Данные и повторные попытки

Имя и телефон не записываются в localStorage или базу сервера. Они используются для сообщения Telegram; после отправки остаются только в памяти открытой страницы и у получателя. В браузере сохраняются параметры визита и результат отправки без контактов. В `sessionStorage` — только случайный ключ попытки и хеш, без исходных контактов. Сервер хранит ID, хеш и состояние попытки до 30 дней, чтобы не отправлять один запрос дважды.

Повтор с теми же данными использует тот же ключ. При явном отказе Telegram можно повторить отправку. Если ответ потерян и неизвестно, принято ли сообщение, сервер не дублирует его: пользователь получает просьбу связаться с клубом. Удаление локальной копии не отменяет заявку в Telegram. Чтобы изменить или отменить заявку, гость связывается с администратором.

API Telegram: [sendMessage](https://core.telegram.org/bots/api#sendmessage), [getUpdates](https://core.telegram.org/bots/api#getupdates).
